# El estándar de los smart contracts

En un entorno EVM, los estándares de smart contracts son, por definición, uno de los pilares más importantes de la Web3. Como analogía, el smart contract es la ley; o, si eres religioso, los evangelios que todos deben seguir.

Los smart contracts en Ethereum comienzan como propuestas **EIP** (Ethereum Improvement Proposals), que son documentos técnicos que describen nuevas funcionalidades o cambios en el protocolo. Aquellas propuestas que definen interfaces y normas para aplicaciones se convierten en **ERC** (Ethereum Request for Comments), que especifican cómo deben comportarse los contratos para ser compatibles entre sí.

Estas normas garantizan la **composabilidad**, permitiendo que en un entorno descentralizado y distribuido todas las DApps hablen el mismo lenguaje y puedan interactuar de forma segura.

Al diseñar una DApp, los estándares elegidos actúan como las piezas de un juego de LEGO: cada ERC es un bloque bien definido que encaja con los demás. La aplicación y el resto del ecosistema podrán interactuar sin fricción solo si esas piezas están bien elegidas. Por eso la selección de estándares es crucial desde la arquitectura del proyecto.

Casi se puede decir que definir una Dapp es elegir estos estándares. Cada ERC actúa como un bloque funcional ya probado, lo que evita partir de un lienzo en blanco y acelera el desarrollo manteniendo la compatibilidad con el ecosistema.

Algunos estándares son básicos, como los que definen un token fungible (**ERC-20**) o un token no fungible (**ERC-721**). Otros son más avanzados, como los que estructuran organizaciones autónomas descentralizadas (DAO) con roles y permisos (**ERC-2535**, etc.).

La claridad y transparencia de estos estándares son esenciales para la interoperabilidad y la evolución del ecosistema.
